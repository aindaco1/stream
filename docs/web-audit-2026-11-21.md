# Stream web audit

November 21, 2026 · Filmmaker workspace, public players and inline checkout · Store sandbox

The pilot’s public signup, film posters, program editor and checkout were tested together. The most consequential fixes were a mobile editor that squeezed film names to zero width, lost keyboard focus after checkout failed, and application files that browsers downloaded again on every visit. The main remaining performance issue is the wait for the first frame of a program preview.

## Search and discovery

| Surface | Verified behavior | Decision |
| --- | --- | --- |
| Home, FAQ and filmmaker agreement | A signed-out visitor gets a readable title, description, heading and server-rendered text. Home and FAQ have one same-origin redirect. | The pilot sends `X-Robots-Tag: noindex`. Decide which pages to index when a stable public origin is available. |
| Dashboard, settings and administration | Signed-out workspace and admin requests redirect to their respective sign-in pages. The authenticated workspace uses private, non-storable responses. | Keep account pages and recovery links out of search. Access control remains necessary for private information regardless of crawler behavior. |
| Film and program players | Direct URLs return the film or program title in HTML. A film description can use its saved synopsis only when the embed includes that field. The program lineup is assembled by JavaScript. Unknown titles return a real 404. | The sandbox players and screening room now consistently send `noindex`, including players containing sample credits. Field selections still govern what an embed reveals. |
| Filmmakers’ websites | The iframe works independently. Its markup does not add a heading or synopsis to the host page’s own HTML. | The FAQ now asks filmmakers to add the title and a short synopsis to the page where they paste their player. |

**At public launch**, choose the canonical HTTPS URLs for the home page and FAQ. Check those pages’ actual response headers from outside the network, include only intended indexable URLs in a sitemap, and verify them in Search Console. The pilot currently returns 404 for both `/robots.txt` and `/sitemap.xml`. Crawlers must be allowed to fetch a page to see its `noindex` directive. [Google’s indexing guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing)

A filmmaker who wants their film found in video search can use a dedicated watch page with a prominent player, descriptive page title and accessible poster image. If Stream later offers video structured data for host sites, supply stable public player and poster URLs, honor the filmmaker’s visibility choices, and keep R2 paths and paid-media URLs private. Search appearance has to be verified on a public site. [Google’s video search guidance](https://developers.google.com/search/docs/appearance/video)

## Accessibility

| Finding | Change and retest |
| --- | --- |
| Two film labels measured 0 px wide in the 320 px program editor. Rows grew to 461–487 px and two checkbox targets failed the spacing check. | Reflowed the rows. Labels measured 198 px wide, rows were 112–113 px high, and the checkbox targets passed. |
| A failed payment-provider request closed checkout and left keyboard focus on the page body. | Focus returns to the selected Rent or Buy button. A browser regression check now exercises the failure path. |
| Some Dashboard sections skipped a heading level, and checkout lacked a visible primary heading. Each program entry announced another landmark called “About the film.” | Corrected section hierarchy, gave the active checkout its own heading, allowed long checkout titles to wrap, and grouped each credit block under its existing title. |
| Opening the signed-in agreement threw a JavaScript error because that page has no selected workspace tab. | The mobile navigation now uses the page heading as its label when no tab is selected. |

Axe-core 4.13.0 checked WCAG A and AA rules through 2.2 and its best-practice rules. The 22 states covered signup, sign-in, FAQ, agreement, filmmaker and admin dashboards, expanded film and program cards and analytics, editor, Storage, Payments, screening room, both poster styles, checkout location/address, and Restore access. Each state ran in desktop Chromium light mode, 320 px Chromium dark mode, 320 px WebKit dark mode, and desktop Chromium with 200% text size. Across those **88 scans**, the tested pages reported zero axe violations and zero horizontal document overflow. Five additional checkout sizes passed with simulated card and contact frames mounted.

Keyboard checks covered skip-to-content, accordion and field-help controls, moving a film in screening order, entering and leaving checkout, recovery email entry and retry after payment-provider failure. Natural VoiceOver and TalkBack speech, physical devices, third-party Turnstile and Stripe frame internals, and the quality of captions or audio description in an actual release film still need manual acceptance. ## Loading and playback

Application JavaScript and CSS now negotiate gzip. Shared static assets have content-based validators so browsers can reuse them across pages and pick up an update immediately. Private pages, access links and video responses retain their existing storage restrictions.

First-party transfer measured in Helium over loopback, in KiB rounded to the nearest whole number. Each route used its own fresh browser context followed by a repeat navigation. Film and program pages requested all detail fields. The screening room contained five embedded players. These are measured transfers for those pages and viewports.

## Priorities before a public release

1. **Profile the first program play.** Measure bucket reads, media inspection, preview generation and client decoding separately on a production-like HTTPS host. The first program play was more than three times slower than any of the individual films in this sample. The measurements do not isolate the cause.
2. **Verify the checkout journey with assistive technology.** On an iPhone with VoiceOver and Android with TalkBack, try signup, a rental, a declined card, recovery, and program navigation with captions. Include the actual provider fields and the system video controls.
3. **Set the public indexing policy and test a filmmaker’s watch page.** Verify the intended canonical, searchable text, poster response, and embed visibility on that site. Keep drafts, orders and private URLs out of the sitemap.
4. **Measure the two remaining large repeat costs.** The program’s main poster and its first film’s lineup thumbnail each transferred about 54 KiB, even when they used the same artwork. Signup transferred about 2 MiB including the managed security check. Test smaller lineup thumbnails and measure real mobile signup completion before changing when the widget loads.
